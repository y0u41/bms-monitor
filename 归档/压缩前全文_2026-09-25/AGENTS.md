## 1. 安全铁律（违反即回滚，不接受"先这样后面再改"）

BMS 误动作 = 停电损失；拒动作 = 起火。以下规则**优先级高于一切功能需求、进度压力与代码美观**。

### 1.1 架构级

| # | 铁律 | 说明 |
|---|---|---|
| **S1** | **保护必须双层** | 硬件层（AFE 内置 OVP/UVP/OCC/**SCD** 比较器 + CHG/DSG 驱动）与软件层（MCU 使能 GPIO）经**与逻辑**合成，相互独立。**禁止**用 MCU 软件承担短路保护（`Tech_Design.md` §5.1） |
| **S2** | **失效安全（fail-safe）** | ① AFE 通信连续 N 次失败 → 进安全态（断开），**不是**维持现状；② IWDG 超时期间硬件层必须仍有效；③ **所有使能信号上电默认为低**，靠**外部 10K 下拉**保证 MCU 死机时也断开 |
| **S3** | **开关常态断开** | 上电后默认断开，需 MCU 明确发出"允许"（`EN_x` 拉高）才可能导通；预充必须先完成且 `V_SW` 达标才闭合主开关 |
| **S4** | **禁止绕过硬件保护** | 任何代码不得关闭/屏蔽 AFE 的比较器与驱动输出；不得为了"测试方便"短接保护回路 |
| **S5** | **三个不可省略的元件** | `EN_x` 外部 10K 下拉、主 MOS 栅极 10K 下拉、预充回路 —— **省略任何一个都会让失效安全失效** |
| **S6** | **AFE 总线必须独占（含软件层的等价要求）** | AFE 的 I²C 走 **PD11/PD12**，**禁止**与 INA226/SHT30/24C02 共用。理由：非安全关键器件卡住总线会导致 AFE 通信失败 → 无意义跳闸。★ **同一个失效模式可以从软件侧发生**（审查 C-39）：软 I²C 驱动若是**单实例·共享失败计数**，SHT30 的偶发 NACK 就会把 AFE 的计数抬过门限 → 一样是无意义跳闸。⇒ 驱动形态必须是**单实现 · 双实例**（`g_bus_afe` / `g_bus_sens`），**每条总线各自独立超时、失败计数与 9 时钟恢复**；⛔ 禁止为了少写代码把三从机并进 AFE 那条总线（无论物理层还是逻辑层） |
| **S7** | **门限层次不得破坏** | 软件三级门限（3.60V/2.80V）**必须比**硬件层门限（3.65V/2.50V）更保守，保证正常情况由软件带日志切断，硬件层只做兜底 |

### 1.2 编码级

| # | 铁律 |
|---|---|
| **S8** | 中断服务函数内**禁止**：Flash 擦写、`printf`、阻塞式 I²C/SPI/UART 等待、浮点密集运算、`malloc` |
| **S9** | **所有对主回路的开关动作必须经过 `app_protect.c` 状态机**，禁止在别处直接写执行器 GPIO |
| **S10** | 开关动作必须满足最小间隔（防振荡）：同一方向两次动作间隔 ≥ `APP_CTR_MIN_INTERVAL_MS`（默认 3000） |
| **S11** | 三级（切断）动作后必须写事件日志并置"锁定"标志；锁定后**只能**由长按 KEY0 5s 解除 |
| **S12** | **禁止**用 `HAL_Delay` / `delay_ms` 在 FreeRTOS 任务里长时间阻塞（>10ms 必须用 `vTaskDelay`） |
| **S13** | 不得删除、注释掉、条件编译掉任何保护判断来"让编译通过"或"让测试通过" |
| **S14** | 门限值**禁止**硬编码在 `.c` 文件中，一律走 `app_config.h` 默认值 + Flash 参数区覆盖 |
| **S15** | **禁止**在 `User/App/*.c` 中出现 AFE 型号相关的寄存器名、`#include`，或执行器引脚宏（`Tech_Design.md` §4.5） |
| **S25** | **Flash 擦写期间不得声称保护有效**：STM32F1 擦写时 CPU 全局停顿 20~80ms（**与任务优先级无关**），软件层必然空窗。参数写入**只允许在 `SAFE_OFF`**；日志**整页写**；写入期间置 `flash_busy`；**禁止在 PVD 中断里写 Flash**（同时违反 S8） |
| **S26** | **AFE ALERT 必须先解码再处置**：BQ769x0 的 ALERT **高有效**且与 `CC_READY` 复用（CC_EN 时每 250ms 跳变）→ **禁止"ALERT 一响就锁定"**，必须读 `SYS_STAT` 区分保护位与 CC_READY |

### 1.3 台架操作（人机安全）

| # | 铁律 |
|---|---|
| **S16** | **必须**在主回路串联 **15A 保险丝**；接线前用万用表测一遍正负极是否短路 |
| **S17** | **必须**在不可燃台面（金属/陶瓷/水泥）上做测试，旁边备**干砂**（锂电池起火不能用水扑，量小时大量水浸也可，但砂最稳） |
| **S18** | 接线顺序：先接采样线束（**从 B− 侧往 B+ 侧逐串**）、后接主回路；拆线顺序相反 |
| **S19** | **任何带电插拔采样线束的行为都视为事故**（接错顺序会立刻炸掉 AFE） |
| **S20** | 每次改动接线后，**先用限流电源（14V/2A 限流）代替电池验证**，确认无异常再接真实电池 |
| **S21** | 大电流（>5A）测试必须有人看护，每级记录 MOS 与分流器温升；**禁止无人看护长时间运行** |
| **S22** | ★ **主回路（B+ / B− / 负载）严禁走面包板与杜邦线** —— 杜邦线（26AWG）安全载流约 1~2A，面包板触点约 0.5~1A。5A 下会发热，且接触电阻使电压读数严重失真（0.1Ω @5A = 0.5V 压降）。**主回路必须用 KF128 / 凤凰端子（★ ≥15A）/ 2.5mm² 导线 / 大电流鳄鱼夹**；杜邦线仅用于信号线。⛔ **KF301 标称仅 10A，不得用于主回路**（15A 上限会超它的额定 —— 审查 C-49） |
| **S23** | **严禁用干电池（碱性/镍氢）或"恒压 1.5V 锂可充"代替锂电做台架** —— 碱性不可充电且内阻高（1A 即致 AFE 误判欠压）；1.5V 恒压锂电**不存在 OCV-SOC 关系**，会使 SOC 算法完全无法验证。唯一可用的过渡是 **12V/3A 适配器 + MP1584 做"假电池"**（可验证采集/执行器/Modbus，**不能验证 SOC 与保护阈值**） |
| **S24** | ★ **低边开关 + 共地仪器 = 保护被旁路**：开关在**负线** ⇒ B− 与"负载负极"是两个节点，示波器/任何接大地的仪器的**地夹只允许接 B−（板地）**；测负载侧节点必须用**差分探头**或双通道相减。**每次改接线后必须测 `负载负 ↔ B−` ≈ V_pack**，才算接线有效（否则保护已被大地短路，且不会报错） |

## 2. 编码纪律

### 2.1 模块边界与数据流

- 数据流**单向，不得反向**：`BSP → app_acq → app_soc → app_alarm → app_protect → BSP(执行器)`。模块职责表见 `Tech_Design.md` §4.2，**越界即违规**。
- `app_acq` 只写原始量；`app_soc` 只写派生量；`app_alarm` 只输出"请求动作"；`app_protect` 是**唯一**能驱动执行器的地方。
- ★ **门限命名空间分域**（审查 C-38）：电池量一律 `APP_BMS_*`、环境量一律 `APP_ENV_*`、**迟滞也分域**；`app_alarm.c` 的语义是**BMS 三级**，继承工程带来的环境两级告警归 `app_env_alarm.c`。`app_protect/app_acq/app_soc` 内**禁止**出现环境门限宏 —— 两套阈值一旦混用就是误动作或拒动作，S7 的门限层次同时失效。（`APP_ALARM_TIME/GAP/CONFIRM/FLASH*` 是**输出通道机制**不是门限，两侧可共用。）
- `User/App/*.c` 里**禁止**出现任何 AFE 寄存器名或执行器引脚宏（S15）。跨实现边界只走 `Tech_Design.md` §4.5 的 `afe.h` / `actuator.h`。

### 2.2 数据与单位（详细表见 `Tech_Design.md` §4.4）

| 量 | 类型 | 单位 | 示例 |
|---|---|---|---|
| 单体电压 | `uint16_t` | mV | 3275 = 3.275V；**0xFFFF = 无效** |
| 总电压 | `uint16_t` | 10mV | 1280 = 12.80V |
| 电流 | `int16_t` | 10mA | **充电为正**，−5000 = 放电 5A |
| 温度 | `int16_t` | 0.1℃ | 255 = 25.5℃ |
| SOC / SOH | `uint16_t` | 0.1% | 855 = 85.5% |
| 累计 Ah | `uint32_t` | mAh | — |

- **电流符号约定：充电为正、放电为负。** 分流器串在 **B+ 正极线**，与此天然一致。
- **所有定标宏集中在 `app_config.h`**，不得散落在业务代码里。
- **浮点只允许出现在 `app_soc.c` 与界面显示格式化处**；其余一律定点整数。
- ★ **单体电压无效值统一为 `APP_MV_INVALID = 0xFFFF`**（**不是 0**）；逐串有效性用 `cell_valid` 位图；遍历一律 `APP_CELL_COUNT`。
- ★ **内部量纲 = Modbus 量纲**（总压 10mV / 电流 10mA / 温度 0.1℃ / SOC 0.1%）：**不允许两套量纲并存** —— 少一层换算就少一处溢出与取整错误（审查 C-22）。
- ★ **AFE 型号与串数由编译期断言守住**（`AFE_CHIP_MIN/MAX_CELLS` + `APP_STATIC_ASSERT`）：**选错型号必须编译不过**（审查 C-01）。

### 2.3 FreeRTOS（详细表见 `Tech_Design.md` §4.3）

| 项 | 规定 |
|---|---|
| 优先级 | **Protect(4) > Acq(3) > Comm(2) > Log(1) = Ui(1)**。**保护任务必须最高** |
| 中断优先级 | ★ **分组必须由 `app_nvic_init()` 钉成 `NVIC_PRIORITYGROUP_4`**（GROUP_4 下"数字 n → 寄存器值 `n<<4`"一比一）。在此前提下：调用 `xxxFromISR` 的中断，抢占优先级数值必须 **≥ 5**（`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`），否则 `configASSERT` 会挂。⛔ **不许用 GROUP_2** —— 它的抢占只有 0~3 档，"≥5"根本写不出来；写 5 会因 `USE_FULL_ASSERT` 未开而**静默**被截断编成 `0x40`（高于内核上限）。落点与断言见 `User/App/app_nvic.c`、审查记录 **C-65** |
| 共享数据 | 多字节结构用互斥量或双缓冲 + 序号，**禁止**用 `volatile` 假装原子 |
| 临界区 | 单次时长 ≤ 100µs；Flash 擦写（80ms）必须在 `TaskLog` 里做 |
| 内存 | **全静态分配，禁止 `malloc` / `pvPortMalloc`** —— ★ 2026-09-25 起由**链接器强制**（`configSUPPORT_DYNAMIC_ALLOCATION=0` + `heap_4.c` 移出工程；实测写一行 `pvPortMalloc(16)` 报 `L6218E: Undefined symbol`，见 `附录C` C-42）。栈实测后用 `uxTaskGetStackHighWaterMark()` 留 30% 余量；开发期 `configCHECK_FOR_STACK_OVERFLOW=2` + `app_tasks.c` 的 `vApplicationStackOverflowHook()`（C-41） |
| 看门狗 | ★ **判活按"逐任务 deadline"**（`now - last_beat > APP_WDG_ALIVE_K × 本任务周期`），**禁止**用"每个任务自上次检查以来都跑过一遍"这种口径 —— 它对检查节拍与任务周期的比值敏感，会把健康的机器判成卡死（审查 C-34）。IWDG 超时 **2s**（原 8s 会吃掉判活余量），三个窗口（任务周期 × K、`APP_WDG_CHECK_MS`、`APP_IWDG_RLR`）的一致性由 `app_config.h` §12.6 的 8 条编译期断言守住。**条件喂狗只允许出现在 `TaskProtect` 里**；⛔ **不得存在"关掉看门狗"的编译期开关**（`APP_ENABLE_IWDG` 已删，S13），由门禁 G7-④ 机械搜索。⚠️ `APP_LSI_HZ` 目前是标称 40kHz，**F1 实际 30~60kHz**，D5 必须实测回填 |

### 5.2 写作纪律

- 区分「**已核实**」与「**推测**」—— 推测必须显式标 `⚠️ 待验证`；
- 不许写"众所周知""理论上应该可以"这类无信息量的话；
- 任何数字必须给出来源（标准号 / 数据手册 / 实测记录），查不到就写"**待实测**"；
- 安全相关结论必须写清**适用条件**与**失效后果**；
- **明确不做的项必须写进差距声明**；
- 语言：中文正文；标识符、命令、路径、寄存器名用英文。文档 UTF-8（`.md`）；给 Keil/Windows 看的 `.txt` 用 GBK。

### 5.3 AI 协作成本纪律

> 背景：2026-09-23 单日 API 消费异常（¥50），根因是**子代理嵌套扇出 × 搜索词扇出 × 高峰时段 × 搜索循环**四重放大。

1. **禁止子代理再派子代理**（一次任务最多一层委派）；
2. `web_search` **每次只传 1 个 query**（多 query 会展开成多次计费的服务端请求）；
3. **撞 WAF/登录墙的站点不重试** —— 记录"价格待核实"并换思路；
4. 批量调研挪到**闲时**（高峰段为工作日 9:00–12:00、14:00–18:00，单价双倍）；
5. 委派必须写清**停止条件**（"最多 N 次搜索 / 最多 M 个文件"，并注明"不要创建子代理"）。

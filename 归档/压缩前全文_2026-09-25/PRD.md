## 1. 定位与冻结规格

### 1.1 一句话定义

做一台**能主动切断主回路**的 4S 磷酸铁锂电池管理系统台架原型：
**采集**（单体电压 / 电流 / 温度）→ **估算**（SOC）→ **三级告警** → **双层保护动作** → **本地显示 + 事件记录 + Modbus 读出**。

### 1.2.2 模块形态与采购路线（2026-09-24 · ✅ **已关闭：原判断是"渠道找错"，不是"买不到"**）

> **结论：`BQ7692003PWR` 在 TI 授权分销商 DigiKey 有充足现货（1,757 片 / ¥35.77）→ 主路线 = 买正品裸芯片 + 复制 TI 官方 EVM（SLVU924）原理图 + 嘉立创打样。**
> 此前"按 bq76920 只搜到裸芯片、无成品模块"是**在淘宝/京东搜消费类保护板**得到的结果 —— 那是**渠道错误**，不是器件缺供；"4S + bq76920 + 引出 I²C 与 CHG/DSG"的模块**市面上确实不存在**，但这一点**已不再构成阻塞**。
> ⛔ **不该再找"模块"**：成品模块 = 裸芯片 + 外围 + **厂商自己的 MCU 与固件**（上一轮判读那块京东「bq76920 开发板」的实证 = 板上带 **RS485 与 `DAC1` 丝印**，而 bq76920 本身既无 UART 也无 DAC），且这类"智能保护板"**不引出 `CHG`/`DSG`** ⇒ 买回来等于把 `afe_hal`、预充、锁定状态机全部删掉，**S1/S3/S4/S9 同时塌陷**。

> ⚠️ **待核实（不影响结论）**：DigiKey 对个人用户的运费与含税口径、国内现货的实际到货时效（一般 2~3 天，⚠️ 待下单验证）；立创商城（LCSC）价格本次未查（成本纪律：挪闲时再核）。

## 2. 功能需求

### 2.1 FR-ACQ · 数据采集

| # | 需求 | 指标 | 级别 |
|---|---|---|---|
| FR-ACQ-01 | 单体电压 | 4 串，误差 ≤ **±5mV**，周期 **100ms** | ★ |
| FR-ACQ-02 | 总电压（双通道） | AFE 组电压 + INA226 总线电压，互校，误差 ≤ **±0.5%** | ★ |
| FR-ACQ-03 | 电流 | 误差 ≤ **±1% FS** 或 ±0.1A 取大者；**充正放负** | ★ |
| FR-ACQ-04 | 温度 | 电芯表面 NTC + 环境 SHT30，误差 ≤ **±2℃** | ★ |
| FR-ACQ-05 | 开关两端压差 `V_SW` | 用于预充判据，误差 ≤ **±2%** | ★ |
| FR-ACQ-06 | 定点滤波 | 电压一阶低通；电流滑动平均；**不得引入 >200ms 的相位滞后** | 重要 |
| FR-ACQ-07 | **数据新鲜度** | 任一通道 > **5s** 未更新 → 标记该通道无效 | ★ |
| FR-ACQ-08 | **断线识别** | NTC 开路/短路、I²C 无应答、AFE 通信失败 → 标记通道故障 | ★ |
| FR-ACQ-09 | **链路一致性校验** | AFE 与 INA226 总压偏差 >1% 持续 5s → 报链路故障；**仅告警，不误切断** | 重要 |
| FR-ACQ-10 | 采样不阻塞 | 三个 I²C 从机各自独立超时，任一卡住不得阻塞其他 | ★ |
| FR-ACQ-11 | **总线死锁恢复** | 任一从机拉死 SDA → 驱动自动发 9 个时钟 + STOP 恢复，**不得依赖断电重启** | ★ |
| FR-ACQ-12 | **单体电压标定** | 每串独立 `k/b` 系数存参数区、掉电不丢；**±5mV 是"逐串标定后、常温"指标** | ★ |

> `firmware/User/App/app_config.h` §12.7（`APP_BMS_*`，一一对应；⛔ 任何 `.c` 里不得再出现第三次数值）。
> **改数值先改本节，再同步宏**；层次关系（单调 + S7 + 迟滞 < 半级差）由宏区的编译期断言把住。

**单体电压**（FR-ALM-01）

| 级别 | 触发 | 动作 |
|---|---|---|
| 一级 | ≥ 3.50V 或 ≤ 3.00V | 记录 + LCD 提示 + 请求降额 50% |
| 二级 | ≥ 3.55V 或 ≤ 2.90V | 记录 + 请求降额 20% |
| 三级 | ≥ 3.60V 或 ≤ 2.80V | **断对应方向开关 + 写日志 + 锁定** |

**温度**（FR-ALM-02，满足任一即触发）

| 级别 | 充电 | 放电 | 温差 | 温升速率 |
|---|---|---|---|---|
| 一级 | ≥45℃ 或 ≤0℃ | ≥55℃ 或 ≤−15℃ | ≥8℃ | ≥0.5℃/min 持续 3 周期 |
| 二级 | ≥50℃ 或 ≤−5℃ | ≥60℃ 或 ≤−20℃ | ≥12℃ | ≥1.0℃/min 持续 3 周期 |
| 三级 | ≥55℃ 或 ≤−10℃ | ≥65℃ 或 ≤−25℃ | ≥15℃ | ≥2.0℃/min 持续 2 周期 |

> **LFP 强制条款**：规格书普遍要求 **0℃ 禁止充电**（防析锂）。若规格书如此，**"0℃ 禁充"应实现为三级动作（切断充电），但归属"环境型"：不锁定、条件回升后自动恢复**（迟滞 ≥3℃ 且持续 60s）。原文把它写成二级"请求降额"是**等级归属错误**（切断 ≠ 请求降额），修正见 `Tech_Design.md` §5.2。

**电流**（FR-ALM-03）

| 级别 | 充电 | 放电 |
|---|---|---|
| 一级 | ≥ 3.6A 持续 5s | ≥ 6.5A 持续 5s |
| 二级 | ≥ 4.2A 持续 3s | ≥ 8.0A 持续 3s |
| 三级 | ≥ 5.0A 持续 1s | ≥ 10A 持续 1s，或**电流突变**（判据：`\|ΔI\| > 5A / 100ms`，**用未经滑动平均的原始值**判定，滤波值会掩盖突变） |

| 硬件层（AFE 内部，不受软件控制） | 值 | 响应 |
|---|---|---|
| 充电过流 OCC | 6A | **1280ms**（可配，★ **手册最大档即 1280ms，没有 2s 档** ⇒ C-70） |
| 放电过流 OCD | 12A | **1280ms**（可配，同上） |
| **短路 SCD** | 30A | **~100µs**（**不可调慢**） |

> ★ **为什么硬件 OCC/OCD 比软件层慢（2026-09-24 审查修正 C-14；2026-09-25 C-70 修正数值）**："软件更保守"**不只是门限更严，还必须动作更早**。
> 软件三级放电门限是 `10A / 1s`，硬件 OCD 是 `12A`：若硬件延迟也是 ~1s，则当电流 >12A 时**两层同时到点**，"软件先动、硬件兜底"在电流维度上就是假的，**F4 类验收必然失败**。
> 改法：**沿时间轴分层** —— 软件层（10A/1s，带日志）先动，硬件层（12A/**1280ms**）后动兜底，间隔 280ms 足够。⚠️ **原写"2s"是错的**：bq769x0 的 `OCD_DELAY` 最大档 = **1280ms**（§7.5 `OCDDELAY`），**不存在 2s 这一档**（`附录C` **C-70**）⇒ 代码侧 `APP_BMS_HW_OCC_OCD_MS` 由 2000 改 **1280**，C-14 的先后关系**不变**。⛔ **SCD 必须保持 ~100µs，不得改慢**（短路时软件来不及，这是物理限制）。
> ⚠️ 本表的 1280ms 与全部硬件门限必须在 **D8 写 AFE 寄存器时逐条对册落实**（`Tech_Design.md` §3.1.1 ④「门限-寄存器对照」+ §5.1；C-67③：**对册前断言只证明自洽，不证明与芯片一致**）。

> **电流门限三选最小**：不得超 AFE 量程、线束载流量（15A）、电芯规格书最大倍率。若规格书最大持续放电倍率 < 1.67C，**必须下调三级门限**。

**温度修正**（FR-ALM-04）：T ≥ 45℃ 充电门限 ×0.5；T ≥ 50℃ ×0.2 或禁充；T ≤ 0℃ **禁充**；放电低温同样降额。

**多参数融合**（FR-ALM-05，满足即**直接升一级**）：高温 + 大电流 + 温升快 → 升三级（热失控前兆）；压差大 + 温差大 → 升二级；电压正常但温升速率异常 → 升二级。

> ⚠️ **数值缺口（2026-09-25，Q12）**：本条用到"压差大"，但 §2.3 三张表里**没有压差的分档数值**
> （只有 §2 FR-SOC-05 要求"算出压差"、FR-HMI-01 要求"显示压差"）。⇒ 没有判据数值，融合规则里
> 这一条无法实现，代码侧只能先把开关置 0（`APP_BMS_CELL_DIF_MV = 0` = 不启用）。
> **D14 之前必须补数值**，否则 FR-ALM-05 只能算"三条融合里做两条"，须写进 §6 差距声明。

**误报抑制**（FR-ALM-06，三层）：确认窗｜迟滞（解除阈值回退：电压 20mV / 温度 1℃ / ~~电流 5% FS~~ **电流 5% × 本级门限**）｜持续性要求（压差需持续 N 周期，避开均衡瞬间）。

> ★ **电流迟滞口径修正（2026-09-25，`附录C` · C-67）**：原写"5% FS"，但无论 FS 取 INA226 满量程
> （±81.92mV / 5mΩ = 16.384A → **0.82A**）还是取设计上限 15A（→ **0.75A**），都**大于本节电流表自己的
> L1→L2 级差 0.6A**（3.6→4.2A）。迟滞窗比级差还宽 ⇒ 一级的**解除点**（2.78A）比二级的**触发点**
> （4.2A）低了一整个二级区间 ⇒ **电流维度的分级失效**（一触发就一路升到三级、恢复时又整段跳过）。
> ⇒ 改为"**5% × 该方向最低级门限**"，并追加一条硬约束：**迟滞必须 < 相邻级差的一半**
> （`app_config.h` §12.7.6 用编译期断言把住，写大了直接编译不过）。
> ⚠️ 同一检查的另一半：**温升速率不叠加迟滞** —— 1℃/min 的迟滞大于该表 L1(0.5)/L2(1.0) 的整个级差，
> 加上去会把速率告警永久卡住；该量靠"持续 N 周期"去抖即可。

> ★ **确认窗必须按等级分开（2026-09-24 审查修正）**：**三级判据不得用 3s 确认窗**（否则与 §4 的"动作 ≤1s"直接矛盾）—— 三级用 **≤200ms 去抖 + 迟滞**；3s 窗只用于一级/二级与易抖动量（压差、温升速率）。
> ★ **保护判定必须用"原始值或轻滤波值"**（尤其电流）：滑动平均会带来 `(N−1)/2 × 100ms` 的群延迟，吃掉三级动作的时间预算。滤波值只用于 SOC 积分与显示。

**可读原因**（FR-ALM-07）：每条告警必须带 ASCII 原因串（如 `cell3 OV 3.62V`），用于 LCD / 日志 / Modbus。**不允许只报警不说明原因。**

**降额责任边界**（FR-ALM-08，必须写清，否则验收争议）

| 级别 | 本机动作 | 对外动作 |
|---|---|---|
| 一级 | 提示 + 记录 | 上报"建议降额" |
| 二级 | 记录 | 发**降额请求**并启动超时计时 |
| 二级超时未应答 | 记录 | **升级为断开对应方向** |
| 三级 | **本机直接切断 + 锁定** | 紧急上报 |

> **边界声明**：本机是**保护装置不是电源调度器**。二级"降额"在 4S 台架上无受控负载可执行，因此**本机只负责"请求 + 超时升级"**，降额本身由上位机/负载完成。这一条必须写进论文，否则评委会认为降额没实现。

### 2.4 FR-PRT · 保护动作（安全关键）

| # | 需求 | 级别 |
|---|---|---|
| FR-PRT-01 | **双层保护**：硬件层（AFE 比较器 + CHG/DSG 驱动）与软件层（MCU 使能 GPIO）经**与逻辑**合成，相互独立。任一层输出低就断开 | ★ |
| FR-PRT-02 | **短路保护只在硬件层**（软件来不及，这是物理限制） | ★ |
| FR-PRT-03 | **失效安全**：AFE 通信连续 N 次失败 → **进安全态（断开）**，不是维持现状 | ★ |
| FR-PRT-04 | **上电默认断开**：所有使能信号默认为低，靠**外部 10K 下拉**保证 MCU 未上电/复位/死机时也断开 | ★ |
| FR-PRT-05 | **不可知即不安全**：任何数据缺失都向保守方向降级，绝不向放行方向降级（电压通道失效 → **禁止充电**；`V_SW` 失效 → **禁止闭合主开关**） | ★ |
| FR-PRT-06 | **预充**：闭合主开关前必须先预充且 `V_SW < 1V`；预充超时 → `SAFE_OFF` 并重试，超限锁定 | ★ |
| FR-PRT-07 | **开关最小间隔** ≥3s，防临界振荡 | ★ |
| FR-PRT-08 | **三级动作后锁定**，只能长按 KEY0 5s 解除 | ★ |
| FR-PRT-09 | **AFE ALERT 触发 → 记为独立事件 + 锁定**（说明软件层没拦住，必须追查） | ★ |
| FR-PRT-10 | 所有开关动作必须经 `app_protect.c` 状态机，**禁止**别处直接写执行器 GPIO | ★ |
| FR-PRT-11 | 参数区 CRC 坏 → 拒绝启动进 `FAULT_LATCHED`，**不得用默认值裸跑** | ★ |

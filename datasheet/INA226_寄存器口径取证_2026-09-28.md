## 2. 器件常量（已进 `ina226.h`）

- 器件地址 **0x40**（A1=A0=GND，模块出厂默认）——`Tech_Design.md` §2/§3.3 已按 0x40 冻结。
- 分流器电压寄存器：**有符号** 16 位，**2.5µV/LSB**，固定增益满量程 **±81.92mV**（手册里没有 PGA 档位可配）。
- 总线电压寄存器：**无符号** 16 位，**1.25mV/LSB**，满量程 **40.96V**。
- CONFIG 位域：见上表第三行；**bit14~12 手册标为固定 `100b`**，⚠️ 本仓库**没取到"写 0 也安全"的原文** ⇒ 驱动既不写 1 也不依赖它们（整字回读比对会告诉我们写进去的到底是什么）。

## 4. 一条与 INA226 无关、但同一轮踩到的同类问题（本机没有手册原文）

`STM32F1` 的 **DMA1 请求映射**（`USART2_RX = Channel6` / `USART2_TX = Channel7`）出自 **RM0008 Table 78**，
而**本仓库没有 RM0008** ⇒ 它的依据只有"一份第三方实现里 `USART1_TX = Channel4` 对得上"这一层。
⚠️ 且 `AGENTS.md` §3.1 ① 说的"当场 grep 设备头"**在这里不管用**：设备头只有通道基址
（`stm32f103xe.h:781~787`），**请求映射是硅片里固定的、设备头与 HAL 都不表达**。
⇒ 兜底 = `firmware/Drivers/BSP/RS485/rs485.c` 的 `rs485_selftest()`（挂错通道 ⇒ `HAL_UART_Transmit_DMA()` **永不完成** ⇒ 自检超时）；
⇒ 第二形态 = 上机读 `DMA1_Channel7` 的 `CNDTR`（`0x40020080`）：**`0` 才说明那 2 字节真的被搬完**。
该纪律已进 `AGENTS.md` §3.1 **⑥**，实测值见 `Build.md` §8.34 / `附录C` C-118。
